# AGENTS.md

Working notes for agents modifying this repository. For the design read
`ARCHITECTURE.md`; for usage read `README.md`. This file covers the repo layout,
how to build and test, the invariants you must not break, and the traps that are
easy to fall into.

## Repo map

```
http_parser.h         Declares the API (init, settings, execute, helpers) and the http_parser / http_parser_settings structs. Header. Verbatim from Xapiand.
http_parser_enums.h   The method / status / errno / state / header-state enums, defined with enum.h's ENUM() macro. Includes "enum.h". Verbatim from Xapiand.
http_parser.cc        The streaming state machine: http_parser_execute() plus helpers. From Xapiand, with the bulk scans listed under "Standalone vs. Xapiand". Includes "likely.h".
likely.h              Self-contained likely()/unlikely() branch hints. Vendored on extraction (no config.h coupling).
test/test.cc          Runnable smoke test: GET, POST+body, byte-by-byte streaming, chunked across two buffers, malformed method, keep-alive.
test/diff.cc          Differential test (CTest `http_parser_diff`): the parser against test/http_parser_old.cc over a corpus, mutations, sweeps and random messages; compares every callback and every parser field.
test/conformance.cc   llhttp's markdown suite (test/llhttp_corpus.inc, generated by tools/llhttp_corpus.mjs) against the parser; the cases where it differs from llhttp are listed in test/llhttp_divergences.txt (CTest `http_parser_conformance`).
test/fuzz.cc          Differential fuzz target on the same oracle: a libFuzzer target, or (HTTP_PARSER_FUZZ_DRIVER) the mutation loop `http_parser_fuzz`, whose short run is the CTest test `http_parser_fuzz`. Every input runs at every split point, with pauses and failures.
test/http_parser_old.cc  Frozen copy of http_parser.cc from before the bulk scans, symbols renamed (http_parser_old_*). Never edit it; test/http_parser_old.h declares it.
tools/mutants.py      Breaks each fast path in about 40 ways and requires test/diff.cc to fail on every one.
bench/bench.cc        A/B benchmark: the parser against the frozen copy, with an A/A arm and llhttp (cmake -DHTTP_PARSER_BUILD_BENCH=ON).
bench/loop.cc         One workload through one parser N times (http_parser_loop): instructions per message under callgrind, or a steady loop for a profiler.
bench/micro_*.cc      Micro benchmarks of the CRLF scan and the URL run against the byte loops and memchr.
examples/demo.cc      A runnable tour (not a test).
CMakeLists.txt        STATIC library `http_parser` (+ alias http_parser::http_parser); FetchContent enum-reflection; CTest tests `http_parser`, `http_parser_diff`, `http_parser_fuzz`, `http_parser_conformance`.
.github/workflows/    ci.yml: the shared matrix, plus a build without the vector code and one non-strict build; fuzz.yml: the nightly fuzz run (x86-64 and arm64, both modes).
LICENSE               MIT. NGINX/Joyent for the parser; Dubalu LLC for the Xapiand additions and extraction wiring.
README.md             What it is, install, quick start.
CHANGELOG.md          Behavior and performance changes, dated.
docs/API.md           The API reference and callback rules.
docs/http-parser.d2   The README diagram's source (docs/http-parser.svg is rendered from it).
ARCHITECTURE.md       Internal design of the streaming state machine, callbacks, body handling, enums.
```

This is not header-only. `http_parser.cc` must be compiled and linked; the
headers only declare the API and the enums. The CMake target is a `STATIC` library
that links `enum-reflection` so `"enum.h"` resolves.

## Build and run the test

```sh
cmake -B build && cmake --build build && ctest --test-dir build
```

Configure with the Homebrew LLVM compiler if you want the family's reference
toolchain:

```sh
cmake -B build -DCMAKE_CXX_COMPILER=$(brew --prefix llvm)/bin/clang++
```

The first configure fetches `enum-reflection` over the network (FetchContent,
`GIT_TAG main`), and that pulls its own transitive deps (perfect-hash, hashes,
static-string, char-classify). Expected output ends with
`all http-parser tests passed`, exit 0. The test target is `http_parser_test`; the
registered CTest name is `http_parser`. A second test, `http_parser_diff`
(`test/diff.cc`, about 1.8 million parses in a few seconds), ends with
`all http-parser differential checks passed`; run it after any change to
`http_parser.cc`, also with `-DCMAKE_CXX_FLAGS=-DHTTP_PARSER_NO_SIMD` and
`-DCMAKE_CXX_FLAGS=-DHTTP_PARSER_STRICT=0` (the byte loops and the non-strict URL
table), and under ASan/UBSan where they run. `http_parser_fuzz` is a short mutation
loop over the same oracle; for a long run build it with ASan and UBSan and give it
`--iters`, or configure clang with
`-DCMAKE_CXX_FLAGS="-fsanitize=fuzzer-no-link,address,undefined" -DHTTP_PARSER_BUILD_LIBFUZZER=ON`
and run `http_parser_libfuzzer` (`--dump-corpus DIR` of `http_parser_fuzz` writes the
seed corpus). `python3 tools/mutants.py BUILD_DIR` checks that the differential test
catches each deliberate break of a fast path. `http_parser_conformance` runs llhttp's own
suite (`test/llhttp_corpus.inc`, 253 cases) and checks the parser against
`test/llhttp_divergences.txt`; `--report` prints every case, `--case LOCATION` one.
Configure with `-DHTTP_PARSER_LLHTTP_SOURCE_DIR=<llhttp release tree>` to run llhttp
itself too (it must reproduce its own logs, which checks the harness), and
`node tools/llhttp_corpus.mjs LLHTTP_CHECKOUT --check test/llhttp_corpus.inc` to check
the corpus against an llhttp checkout. `cmake -DHTTP_PARSER_BUILD_BENCH=ON`
adds `http_parser_bench` (A/B against the frozen copy; run it under a quiet
machine). The tests and demo are only added when this
repo is the top-level project (CMakeLists.txt), so consumers vendoring it via
`FetchContent` won't build them.

## Dependency

`http_parser_enums.h` includes `"enum.h"` and defines its enums with the `ENUM()`
macro. That header lives in the sibling
[enum-reflection](https://github.com/Kronuz/enum-reflection) library, pulled in by
CMake and linked `PUBLIC` so the include path resolves (the public header chain
`http_parser.h` -> `http_parser_enums.h` -> `"enum.h"` reaches consumers, hence
`PUBLIC`). We track its tip with `GIT_TAG main`, like the rest of the family. This
is the library's only external dependency. The implementation's other include,
`"likely.h"`, is satisfied by the vendored copy in this repo, not a dependency.

## Conventions

- **C++20.** The target requests `cxx_std_20` `PUBLIC` to stay uniform with the
  sibling libraries. Don't drop the target below it.
- **The implementation is compiled as C++.** That is deliberate: it is what makes
  `enum.h`'s C++ machinery (and so the enum-reflection dependency) load-bearing,
  and it matches the C++20 family. The file is named `http_parser.cc` rather than
  `.c` so the C++ compile is first-class, not the deprecated "treat .c as C++"
  path.
- **Header filenames are stable.** `http_parser.h` and `http_parser_enums.h` keep
  their original Xapiand names so a consumer that already `#include`s them just
  needs this repo on the include path. Don't rename the headers.
- Tabs for indentation in new code, double quotes in code, no em dashes in prose.
- MIT-licensed; keep the existing copyright headers on the source files (the
  NGINX/Joyent header on `http_parser.h` / `http_parser_enums.h` /
  `http_parser.cc`, the Dubalu header on `likely.h`).

## Load-bearing invariants

- **The data callbacks can fire more than once per logical value.** `on_url`,
  `on_header_field`, `on_header_value`, and `on_body` each deliver slices of the
  caller's buffer and may be called repeatedly as a run straddles buffer
  boundaries. Any consumer (including the test and demo here) must *append*, not
  assign, and treat a header-field callback after a header-value callback as the
  start of a new pair. Don't write a test that assumes a value arrives whole.
- **`content_length` counts down, it is not the header value.** It is loaded from
  `Content-Length` and decremented as body bytes are delivered, reaching `0` at
  `on_message_complete`. Reading it after a complete parse gives `0`. The test
  asserts exactly this; don't "fix" it to expect the header number.
- **`http_errno_name()` returns the `HPE_`-prefixed token.** The string table is
  generated as `"HPE_" #n`, so the name is e.g. `"HPE_INVALID_METHOD"`, not
  `"INVALID_METHOD"`. Assertions must match the prefixed form.
- **The parser is streaming; `execute()` returns bytes consumed.** On malformed
  input it stops and the return is short of the input length, with
  `HTTP_PARSER_ERRNO(parser)` set. Check the errno after every call, not just the
  return.
- **The enums come from `enum.h`'s `ENUM()` macro.** Don't replace them with plain
  C enums or you break the reflective accessors and the dependency's reason to
  exist. The X-macro maps (`HTTP_METHOD_MAP` etc.) feed both the enums and the
  string tables, so edit the map, not the two outputs separately.

## How to extend

- **Add a request method.** Append to `HTTP_METHOD_MAP` in `http_parser_enums.h`
  (the X-macro feeds both the `http_method` enum and `method_strings`). The
  parser's method-matching trie in `http_parser.cc` then needs the new verb wired
  into its character dispatch; this is the fiddly part, mirror an existing verb of
  the same first letters.
- **Always extend the smoke test.** `test/test.cc` is the only executable check
  for the API. Add a case for any new behavior and assert the exact parsed method / url /
  headers / body, following the append-based collector already there.
- **A change to the parse loop must pass `http_parser_diff`.** It compares the
  parser with the frozen `test/http_parser_old.cc` on every callback and every field
  of `struct http_parser`, so it also holds a fast path to the byte-at-a-time result.
  It runs every input twice: with `lenient_http_headers` set (equal in every event and
  field) and without it (equal in the events and the public fields, except that the
  parser may stop early with a hardening error).
- **A change to what the parser accepts must pass `http_parser_conformance`.** A case of
  llhttp's suite that starts or stops differing fails it until
  `test/llhttp_divergences.txt` says so, with a category. Each hardening check is one
  `if (!lenient ...)` in the state that sees the byte; add it to the hardening sweep in
  `test/diff.cc` and a mutant that removes it to `tools/mutants.py`. A rule that changes
  framing without an error (the connection closing after an HTTP/1.0 message with
  `Transfer-Encoding`, no body for a 1xx, 204 or 304 response, Upgrade only on a 101), or
  that stops with an error the frozen parser also uses (`HPE_UNEXPECTED_CONTENT_LENGTH` for a
  response with `Transfer-Encoding` and `Content-Length`), is a named class in
  `changed_class()` in `test/diff.cc`: the only place the strict parser may differ from the
  frozen one other than by stopping with a hardening error, and every class must be reached
  by the inputs.
  Add the new path's boundary cases to `test/diff.cc` (a sweep over every byte value
  at every position, and a buffer that ends inside the run), add its mutants to
  `tools/mutants.py`, and check that every one of them is killed.

## Traps

- **A bulk scan must not skip the byte that crosses `HTTP_MAX_HEADER_SIZE`.** Each
  byte of a URL or header run counts against `nread`; the runs stop short of the
  limit so the byte-at-a-time path reports the overflow at the same offset. A scan
  that adds the whole run and checks afterwards moves the error.
- **A vector scan reads only whole 16-byte blocks inside its span.** Reading the
  block that straddles the end of the buffer is a harmless-looking out-of-bounds read
  that AddressSanitizer flags. Keep the byte loop for the tail.
- **Every hardening check is off when `lenient_http_headers` is set.** That flag is the
  documented way back to 2.7.1, and `test/diff.cc` relies on it to compare with the
  frozen parser exactly.
- **`find_crlf` stays out of line.** Inlined into `http_parser_execute()` the vector
  code changes its register allocation and slows every state, by up to 1.5x on a
  request line. Re-measure with `bench/bench.cc` before touching the attributes.
- **Both copies of the parse loop stay out of line.** `execute<lenient>` is
  `HTTP_PARSER_NOINLINE`: inlined into `http_parser_execute()` the two copies share one
  register allocation, and the strict one loses what the template is for. A `!lenient`
  check is free in either copy; a flag read into a local (as 2.7.1 did) is not, on
  x86-64.
- **A direct transition counts its byte like the loop head.** `NEXTCHAR_COUNTED()`
  is for a target state at or below `s_headers_done` (it adds to `nread` and checks
  the limit), `NEXTCHAR()` for the body states (nothing is counted). The wrong one
  moves the overflow error or lets a long line through.
- **A `goto` enters the target state's own code.** Do not copy a state's body into
  the path that precedes it: the next rule added to that state (a flag, a check)
  would then apply on the loop path and not on this one.
- **Set the state before the callback or the jump.** A callback that pauses or
  fails returns with whatever state was set, and `execute()` resumes there.
- **Do not edit `test/http_parser_old.cc`.** It is the oracle.
- **Compiling the implementation as C silently changes the enums.** `enum.h` gates
  its C++ machinery behind `#ifdef __cplusplus`; built as C, `ENUM()` collapses to
  a plain enum and the reflective accessors and the enum-reflection dependency
  vanish. Keep the source `.cc` and the target a CXX target.
- **`likely.h` is vendored, not the dependency.** It is a tiny self-contained
  branch-hint header. Don't try to resolve it against enum-reflection or reintroduce
  Xapiand's `config.h`-coupled version.
- **The headers still carry the C `extern "C"` and `<sys/types.h>` baggage** from
  upstream. That is intentional for ABI compatibility with the original; leave it.

## Standalone vs. Xapiand

This is a standalone extraction from
[Xapiand](https://github.com/Kronuz/Xapiand), which itself vendored and adapted
the Joyent/Node.js `http_parser`. The headers and the implementation were copied
from Xapiand's in-tree copy. The extraction deltas are small and mechanical: the
one local include `"enum.h"` is resolved against the sibling enum-reflection
library through CMake, the `"likely.h"` include is satisfied by a vendored
self-contained copy (dropping Xapiand's `config.h` coupling), and the
implementation file was renamed `http_parser.c` -> `http_parser.cc`. The parser
logic is Joyent 2.7.1 plus these local changes, all in `http_parser.cc`, all
behavior-identical (see ARCHITECTURE.md, "Bulk scans and direct transitions"):
`find_crlf` and `find_value_end` (one pass, 16 bytes at a time), `skip_url_chars` and its use in the URL
states, the `HTTP/d.d` CRLF shortcut at `s_req_http_start`, the CR LF shortcut at
the end of `s_header_value`, and the direct transitions through the header line, the chunk
frame and the end of the headers. Each is a separate hunk (and a separate commit) so the planned
refresh below can re-apply or drop them one at a time; any other edit here should
stay reconcilable with upstream as a plain diff. The hardening checks (ARCHITECTURE.md,
"Strictness") carry upstream's 2.8-2.9.4 request-framing fixes and llhttp's rules.

Consumed by [Kronuz/http](https://github.com/Kronuz/http) (the HTTP application
layer). The method table is fixed (`HTTP_METHOD_MAP`, 30 methods): any other method is
`HPE_INVALID_METHOD`. It holds Xapiand's verbs (`CHECK`, `CLOSE`, `COMMIT`, `COUNT`,
`DUMP`, `FLUSH`, `INFO`, `OPEN`, `QUIT`, `RESTORE`, `UPDATE`, `UPSERT`, `WAL`), which
stock llhttp rejects; llhttp regenerated with the same table accepts the same set
(`docs/perf/llhttp-evaluation.md`).

**Upstream fixes:** the fork is version 2.7.1; the Joyent upstream's final release is
2.9.4. The hardening carries upstream's framing and memory-safety fixes (9f489a4,
9ce7316, 01da95f, 3502589, 2a0d106, 7d5c99d, and 05525c5, Upgrade only on a 101); the
callback ones (3b0da34, `on_status` without a reason; 25de6ed, one `on_message_begin`
after leading CRLFs), a7c2e86 (`nread` at a buffer boundary), 3123273
(`parse_url("")`) and 0ae8d93 (runtime header limit) are not in. Keep edits reconcilable so that each
can still be applied as a plain diff.
